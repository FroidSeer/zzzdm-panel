# zzzdm 推送面板

> 把 Telegram 频道 [@zzzdm](https://t.me/s/zzzdm)（真正值得买）的每日好价，自动整理成「一张看得懂的图」，定时推到你自己的微信——企业微信群机器人、Server 酱、PushPlus、公众号，想用哪个用哪个。

![推送面板截图](assets/screenshot.png)

---

## 这个项目解决什么问题

「真正值得买」是个很实在的导购频道，但它有三个不方便：

1. **只有 Telegram** —— 国内日常用微信的人，不会为了看几个好价专门挂梯子刷 Telegram。
2. **信息太密** —— 一天几十上百条，母婴、纸尿裤、宠物粮混在一起，真正想看的被淹掉。
3. **手机上看不出重点** —— 频道里的价格、商家、值率散落在几行文字里，滑过去就忘了。

这个面板做的事就是：**每天定时把频道内容捞下来 → 按你的口味过滤 → 重新排成一张图 → 推到你自己的微信**。

不需要服务器，不需要注册任何服务，就是在自己电脑上跑一个 `python` 脚本。

## 亮点

### 一、一条消息 = 一张图，微信里看着就舒服

企业微信的 webhook 一条消息只能是「纯文字」「单张图」或「图文卡片」三选一，做不到「图 + 文字」混排。所以这个项目把**商品首图、到手价、品名、商家、值率、优惠券，再加上一个下单二维码，全部绘制成一张图片**再发出去。

结果就是：群里看到的是干净的一整张图，价格在最上面红色大字，扫右下角二维码直接下单——不会出现「图片一条、说明一条」的割裂感，也不是那种点开才看得清的小卡片。

> 图片链接点不动的问题，用右下角二维码解决了。
> 单图超过企业微信 2MB 限制时，会自动逐步降质重编码，兜底到能发出去为止。

### 二、四个通道，可以同时开

面板右上角的通道按钮可以多选，**同一批帖子会按顺序各推一遍**：

| 通道 | 适合谁 | 需要什么 |
| --- | --- | --- |
| 企业微信群机器人 | 有群、要图文合成卡片 | webhook key |
| [Server 酱](https://sct.ftqq.com/) | 想推到自己的微信服务号 | SendKey |
| [PushPlus](https://www.pushplus.plus/) | 同上，国内访问更稳 | token |
| 公众号模板消息 | 有自己的公众号（含测试号） | appid / secret / openid / 模板 id |

- 只开一个也行，全开也行，推送顺序固定，进度按通道累加显示
- 公众号通道受官方限制（只能发给已关注用户、字段只渲染纯文本），所以它按「一条帖子一条消息」发，正文字段用 `{占位符}` 模板自己配
- 每个通道都能单独「发一条测试」，先在面板里试通再上定时任务

### 三、推送不是黑盒：先确认、有进度、能中途停

「点一下发两百条」是不可逆操作，所以推送这条链路做了三层保护：

- **分级确认** —— ≤10 条直接发，不打扰；>10 条弹确认框，写清「用哪些通道、发多少条、大概几分钟、**已经发出去的不能撤回**」；≥30 条确认按钮变成红色
- **实时进度** —— 页头显示「已发 37/173」进度条，跨通道累计，卡住了能一眼看出来
- **可以中止** —— 点「中止」后，服务端发完当前这一条就停，日志里写明停在第几条；已经进群的消息收不回来，这点面板会提前告诉你

再往下还有一层常规控制：

- 勾选若干条 → 「推送勾选」只发这些
- 「推未推送」只发没发过的，重复点击不会刷屏
- 「全部重推」才是无视记录全量重发，单独放在设置面板里，避免手滑
- 每条卡片都有「已推送」时间徽标，清楚知道哪些发过了

### 四、排除关键词有「大类目录」，一次勾掉一整类

不用一个一个词地加。面板顶部是一条大类导航栏，内置 **10 个大类、49 个小类、350 个词**：

母婴 · 美妆个护 · 户外 · 服饰鞋包 · 食品饮料 · 家居 · 数码家电 · 宠物 · 医药保健 · 汽车

- 点一下大类 → 整类商品被排除
- 展开「细分小类」→ 可以只排除「纸尿裤」而不排除「玩具」
- 三态勾选框：全选 / 部分选中 / 未选，一眼看清状态
- 被排除的 chip 标红 + 删除线，跟「选中」用的品牌橙彻底区分开，不会看错状态
- 你自己加的词不会被目录操作误伤，「清空大类」只清目录里的词

**改完立即生效** —— 加一个词，已经抓下来的帖子会当场重新分拣，命中的从列表挪到「已排除」，不用重新抓一遍。

### 五、服务端定时，关掉网页也照跑

定时任务跑在 Python 后端，不是浏览器的 `setInterval`。设好「每天 9:30」，关掉浏览器、最小化窗口都不影响。

- 只在到点后 30 分钟内触发一次，服务起晚太多就当天不补跑，**避免一开电脑就给你刷一百条**
- 可以顺带勾上「抓完自动推送」，也可以只抓不发、等你自己挑

### 六、白天 / 夜间两套主题

右上角一键切换，跟随系统偏好，刷新不闪白。

![白天与夜间主题](assets/theme-compare.png)

### 七、关键词可以导入导出，能备份也能分享

排除列表支持 `.txt` / `.md` 导入导出，一行一个词，注释行自动忽略。想换台电脑、想把自己的词表发给朋友、想版本化管理，都可以。

### 八、零第三方依赖（后端）

`tg_zzzdm_to_wecom.py`、`webui_server.py`、`push_channels.py` **纯 Python 标准库**，不用 `pip install` 任何东西就能跑。只有两个可选增强：

| 可选包 | 缺了会怎样 |
| --- | --- |
| `Pillow` | 图+文合成退化为「图一条、文字一条」 |
| `qrcode` | 卡片右下角不画二维码，只留链接文字 |

前端是 React + Vite + Tailwind，构建一次出静态文件，之后不装 `node_modules` 也能跑。

### 九、抓取不登录，不碰 Telegram API

走 `https://t.me/s/<channel>` 的公开预览页，纯 HTTP 抓取：不需要 API ID、不需要 session 文件、不需要手机号验证，也就没有被封号的风险。

## 界面速览

一屏分四块，从上到下、从左到右：

- **页头**：通道多选（`企业微信` / `企业微信 +1` / `未启用通道`，点开勾选）、主题切换、刷新抓取、推未推送；推送进行中这里会多一条「已发 37/173」进度条和「中止」。
- **页头下面那条导航**：排除大类 chip，右端是「已排除 2 类 · 7 类部分 · 自定义 29」统计和「细分小类」入口——它在任何窗口宽度下都固定在右端，不会被 chip 挤出去。
- **主区**：今日统计三卡 → 时段分布柱状图 → 搜索栏 → 帖子卡片（≥1280px 两列，缩略图 + 价格 + 商家/值率/券 + 两行推荐语）。窄屏自动收成单列，页头动作也只留图标。
- **右栏**：「推送设置」与「运行日志」两个折叠面板，配置、定时、清空推送记录、全部重推都收在这里，不占主区空间。

## 快速开始

### 1. 准备

- Python 3.8+（Windows / macOS / Linux 都行）
- Node.js 18+（只在需要改前端时用）
- 至少一个推送通道的凭据（企业微信群机器人 webhook key 最省事）

> 拿 key 的方式：企业微信群里 → 右上角 → 群机器人 → 添加 → 复制 webhook 地址，`key=` 后面那串就是。

### 2. 配置

```powershell
Copy-Item ui_config.example.json ui_config.json
```

打开 `ui_config.json`，把 `"key"` 填成你的 webhook key。想用别的通道，也可以直接在面板里填，会自动写回这个文件。

### 3. 构建前端（只需一次）

```powershell
cd ui
pnpm install
pnpm build
cd ..
```

用 `npm install && npm run build` 同样可以，仓库里的 `pnpm-lock.yaml` 只是锁定了作者用的版本。

### 4. 启动

```powershell
python webui_server.py
```

浏览器打开 <http://127.0.0.1:8765/>，点右上角「刷新抓取」就能看到今天的帖子。

### 只想要命令行版？

不想用面板、只想跑一次抓取推送：

```powershell
$env:ZZZDM_WEBHOOK_KEY = "你的 key"
python tg_zzzdm_to_wecom.py
```

常用参数：

```bash
python tg_zzzdm_to_wecom.py --dry-run          # 只打印预览，不发送
python tg_zzzdm_to_wecom.py --hours 24         # 取最近 24 小时（默认是今天 0 点至今）
python tg_zzzdm_to_wecom.py --latest 10        # 只发最新 10 条
python tg_zzzdm_to_wecom.py -p http://127.0.0.1:7890   # 指定代理
python tg_zzzdm_to_wecom.py --exclude 白酒,啤酒 # 临时追加排除词
python tg_zzzdm_to_wecom.py --no-exclude-defaults      # 不套用内置母婴关键词
python tg_zzzdm_to_wecom.py --tz 8 --no-images # 指定时区 / 只发纯文字
```

Windows 上还可以用 `run_zzzdm.bat`（读 `ZZZDM_WEBHOOK_KEY` 环境变量），配合任务计划程序做系统级定时。

## 配置项说明

`ui_config.json` 由面板「推送设置」自动维护，也可以手工改：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `key` | string | 企业微信群机器人 webhook key（**别提交到仓库**） |
| `proxy` | string | 抓取 Telegram 用的 HTTP 代理，留空则直连 |
| `tz` | number | 时区偏移，默认 `8.0` |
| `exclude` | string[] | 排除关键词列表，命中即过滤 |
| `filter_enabled` | bool | 是否启用关键词过滤 |
| `latest` | number | 只展示/推送最近 N 条，`0` 表示全部 |
| `push_images` | bool | 是否合成图文卡片推送（关掉则发纯文字） |
| `auto_refresh_sec` | number | 面板自动刷新间隔，`0` 关闭 |
| `auto_push` | bool | 定时抓取后是否自动推送 |
| `daily_time` | string | 每日定时执行时刻 `"HH:MM"`，空表示关闭 |
| `skip_pushed` | bool | 是否跳过已推送过的帖子 |
| `channels` | object | 各推送通道的开关与凭据，见下 |

`channels` 下面四个子对象，`enabled` 为 `true` 的通道会按 `wecom → serverchan → pushplus → mp` 顺序依次推送：

```jsonc
"channels": {
  "wecom":      { "enabled": true },                                   // 用顶层 key
  "serverchan": { "enabled": false, "key": "SCT..." },
  "pushplus":   { "enabled": false, "token": "..." },
  "mp": {
    "enabled": false,
    "appid": "", "secret": "",        // 公众号 appid / secret（测试号也行）
    "openid": "",                     // 收消息的人，只能发给已关注用户
    "template_id": "",                // 模板消息 id
    // 字段位置和顺序由你在公众号后台选的模板决定，这里只管内容。可用占位符：
    //   {head} 价 + 品名 · {name} 品名 · {price} 到手价 · {shop} 商家
    //   {price_note} 价签备注 · {coupon} 优惠券 · {value} 值率 · {url} 链接
    //   {photo} 首图 · {time} 发布时间 · {text} 正文前 120 字
    "fields": {
      "first":    "{head}",
      "keyword1": "到手 ¥{price}",
      "keyword2": "{shop} · {price_note}",
      "remark":   "👉 {url}"
    }
  }
}
```

## 本地数据（都在这台机器上，不进仓库）

| 路径 | 内容 |
| --- | --- |
| `ui_config.json` | 配置，含 webhook key 等凭据 |
| `ui_config.json.bak` | 上一版配置自动备份 |
| `ui_state.json` | 已推送记录、定时任务上次运行时间 |
| `logs/YYYY-MM-DD.log` | 每日运行日志 |

配置采用「临时文件 + fsync + 原子替换」写入，断电或强杀进程不会写出半个 JSON；解析失败会把坏文件备份成 `.broken` 再回退默认值，不会静默丢配置。

## 常见问题

**Q：抓不到内容？**
Telegram 在国内需要代理。在面板「推送设置 → 代理」里填 `http://127.0.0.1:7890`（按你的客户端改）。部署在境外服务器上可以留空。

**Q：推送的图里没二维码？**
装一下 `pip install qrcode`。不装也能用，只是右下角只有链接文字。

**Q：能不能推给多个群？**
企业微信群机器人是「一个 key 对一个群」，这点绕不过去。但你可以同时把 Server 酱 / PushPlus / 公众号打开，一条帖子多发几个地方；真的要推多个企微群，就复制一份目录、改 `ui_config.json` 里的 key 和端口。

**Q：点了中止，已经发出去的会撤回吗？**
不会。webhook 没有撤回接口，中止只是让「还没发的」不再发。面板在确认框里会明确写这句，别在确认框里闭眼点。

**Q：能不能部署到服务器上？**
可以，`python webui_server.py --host 0.0.0.0 --port 8765`。但面板**没有鉴权**，公网暴露等于把配置和推送能力交出去，务必套 Nginx Basic Auth 或只在内网访问。

**Q：定时不准？**
定时任务在到点后 30 分钟窗口内触发，服务没启动的那段时间不会补跑。想严格准点，用系统任务计划程序调 CLI 更可靠。
